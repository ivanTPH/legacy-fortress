The same content is in design_handoff_legacy_fortress 5.21/VAULT_ACCESS.md for the coding agent. This is a design addition: the data model below is a proposal to identify what's needed, not an instruction to build it. It needs owner approval first. Linked People PR 1 (feat/v52-linked-people-data, ccde902) is kept as it is.

x1Rules

  1. Five separate facts: contact and links, invitation, identity, nomination (later), access (now). Only access opens anything.
  2. Access is created only by the permission service: the owner's Give access, an approved release, or a confirmed and activated legal authority. Links, invitations, ID checks and nominations never create it.
  3. A whole-Vault nomination is one Vault-level record. Never simulate it with record links.
  4. Every confirmation states current access in words: "Access now: none" (nomination, authority) or "Access starts as soon as you confirm" (sharing now).
  5. Before release a nominee sees only that they're nominated, the kind and the state. Never record names, counts, values, documents or scope.
  6. Emails and notifications carry no record names, values or scope.
  7. Release needs all four steps: death reported, evidence checked, death verified, release approved. The nominee must be ID verified. Reporting a death alone never opens anything.
  8. Power of Attorney: the type limits what can ever be seen; the owner can narrow it, never widen it. Identity, validity of the authority and "usable now" are three separate checks.
  9. The owner can stop, cancel or withdraw any access at any time. It takes effect immediately, is written to Record history, and the person is told without details.
  10. Whole-Vault scope includes records added later, minus the owner's exceptions. Exceptions are never shown or counted to the nominee.
  11. Other Vaults the owner is linked to, the Partner portal and Platform Admin are never part of Vault access.
  12. Family default is "After I die". Sharing the whole Vault now is allowed but warned; selected records is the default for sharing now.

x2Where it lives

  • People & Access › new Vault access tab (va-v1 mobile, va-w1 web): Can see now · Nominated for later · Legal authority · Ended.
  • Person page › Vault access card gains Now and Later rows (va-n1, va-n7). Primary action: Set up Vault access.
  • Set-up steps: kind → scope → release → plain-English check → confirm (va-n2–n6). Web: one centred dialog (va-w3, va-w4).
  • Sharing now ends in the existing Give access save (va-s3). Shown on each record with the existing access badge (va-s5, AGENTS rule 27).
  • Recipient: invitation and ID check reuse Journeys 2 and 3; locked state in the Vault switcher (qm2); release tracker joins Journeys 6c (va-r7).
  • Early access requests become a Needs you item in the owner's To do (va-v7).

x5Acceptance criteria (adds 13–26; Linked People 1–12 unchanged)

  1. From People & Access, the owner nominates a person for the whole Vault after death. It's saved as one Vault-level nomination and no record links are created.
  2. A whole-Vault nomination includes records added later; exceptions are never visible or counted to the nominee.
  3. A selected-records nomination covers only the chosen records; new records aren't added.
  4. Confirming a nomination or recording an authority creates no access grant, and the check screen says "Access now: none".
  5. Before release, the nominee's screens and API return no record names, counts, values, documents or scope.
  6. Reporting a death changes no access. Access starts only after release approval, and only for an ID-verified nominee.
  7. Sharing now grants access only on Give access, only to the selected records, and stops automatically on its end date.
  8. Power of Attorney: access only when ID is verified, the authority is confirmed and activation is recorded; scope never exceeds the authority type; withdrawal stops access at once.
  9. The owner can stop access, cancel a nomination or withdraw an authority at any time; it's immediate, recorded in Record history, and the person is told without details.
  10. Executor, attorney, spouse, child, beneficiary or nominee status never grants access by itself (tested in combination).
  11. Vault access never includes other Vaults, the Partner portal or Platform Admin.
  12. An early-access request creates an owner To do item; nothing is shared unless the owner completes Give access.
  13. Emails and notifications contain no record names, values or scope.
  14. V5.2 accessibility on every new screen: 13px minimum, 44px targets, light and dark, labelled controls, logical focus order.

x6Open questions for the owner (and a solicitor where legal)

  1. "Wait for the grant of probate": offered as an option, the default, or not at all?
  2. Who can report a death: the executor only, any nominee, or anyone connected?
  3. "Only if I lack mental capacity": what evidence is needed, who decides, and is the owner told first?
  4. Does access given during the owner's lifetime pause or end when a death is reported? (Drawn: paused.)
  5. Are Wills excluded from an attorney's scope, or shown read-only?
  6. Is a nominee told the scope (whole Vault or selected) before release? (Drawn: no.)
  7. Does an estate release need confirmed executor authority, or is a verified death enough?
  8. Health and welfare LPA: which Vault areas does it map to? There's no health area today.
  9. Checking the register: done by a reviewer by hand, or through the Office of the Public Guardian's service?
  10. Several nominees: released together (drawn) or in an order the owner sets?
  11. Nominee invitation expiry (drawn: 30 days) and reminders.
  12. "View and suggest changes" when sharing now: allowed for everyone or professionals only?
  13. Carried over: a firm as a person or an organisation.
